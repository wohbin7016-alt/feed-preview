# 모아 — 피드 미리보기

사진을 추가하고 순서를 바꿔 인스타그램에 올리기 전 분위기를 확인하는 작은 한국어 웹앱입니다. 로그인, 자동 게시, 캡션, 분석, 사진 서버 전송 기능은 없습니다.

## 로컬 실행

Node 또는 빌드 도구, 외부 패키지가 필요하지 않습니다. Python 3이 있다면 프로젝트 폴더에서 실행하세요.

```sh
python3 -m http.server 8080 --directory public
```

브라우저에서 `http://localhost:8080`을 여세요. 파일을 직접 여는 `file://` 방식은 지원하지 않습니다. 배포할 때는 `public/` 안의 정적 파일만 HTTPS 호스트에 올리면 됩니다. 하위 경로 호스팅도 지원합니다.

## 사용법

- 사진 여러 장 선택 또는 파일 드롭. 새 사진은 선택 순서대로 맨 앞에 추가됩니다.
- 3:4 / 1:1 미리보기 전환. 사진을 자르거나 원본 파일을 바꾸지는 않습니다.
- 사진 선택 후 앞으로 / 뒤로 / 삭제. PC 드래그, 휴대폰 350ms 길게 누르기 후 드래그, 방향키 순서 변경을 지원합니다.
- 마지막 삭제 1건을 되돌릴 수 있습니다. 사진·순서·비율·삭제 취소는 새로고침 후에도 유지됩니다.
- 설치 가능한 브라우저의 앱 설치 또는 iPhone Safari의 공유 → 홈 화면에 추가를 사용할 수 있습니다. 첫 방문이 완료되면 오프라인에서도 사용할 수 있습니다.

## 저장 방식과 제한

모든 사진은 **현재 기기의 현재 브라우저 IndexedDB에만** 저장됩니다. 기기 간 동기화/백업은 없으며 사이트 데이터 삭제, 브라우저 정리 또는 비공개 모드 종료 등으로 사진이 사라질 수 있습니다. 사용자 원본은 그대로 유지하고 긴 변 최대 1,600px JPEG 미리보기 사본을 저장합니다. 투명 영역은 흰색으로 표시됩니다.

최대 100장, 원본 파일당 30MB. 실제로 해독 가능한 이미지 파일만 허용하며 브라우저가 지원하지 않는 HEIC 등은 건너뛰고 안내합니다. 실시간 동영상/애니메이션 재생은 제공하지 않습니다. 실제 인스타그램 화면의 크롭 및 UI와 동일함을 보장하는 앱은 아닙니다.

저장은 직렬 처리되고 사진/배치가 하나의 IndexedDB 트랜잭션으로 반영됩니다. 트랜잭션 완료 전에는 저장 성공으로 표시하지 않습니다. 할당량 초과·쓰기 실패 시 기존 상태가 유지됩니다. 동시 탭 충돌은 revision 검사로 감지해 최신 상태를 다시 불러옵니다.

## 구성

- `public/index.html`, `styles.css`: 반응형 한국어 UI
- `public/app.js`: 이미지 준비, 편집, 키보드/마우스/터치 상호작용
- `public/storage.js`: IndexedDB 저장/불러오기
- `public/manifest.webmanifest`, `sw.js`: 하위 경로 대응 PWA, 앱 셸 오프라인 캐시

앱 셸을 변경하여 배포할 때 `sw.js`의 캐시 버전도 올려 주세요. 캐시 정리는 앱의 현재 scope에만 적용됩니다. 사용자 사진은 서비스 워커 캐시에 저장되지 않습니다.

## 검증 (2026-11-10)

Aside의 실제 Chromium 브라우저에서 합성 이미지만 사용했습니다.

- 390px 모바일 화면과 1280px PC 화면, 3열 유지·가로 넘침 없음
- 다중 사진 추가, 3:4/1:1 전환, 버튼·키보드·마우스 드래그 정렬
- 새로고침 후 사진·순서·비율 보존, 삭제 후 새로고침·되돌리기
- 손상 파일 제외 후 정상 사진 추가, 저장 실패 시 기존 배치 보존
- 서비스워커 준비 뒤 로컬 서버를 종료하고 새로고침: 앱·사진 표시 정상
- 사진 추가·배치 중 외부 네트워크 요청 없음
- 합성 TouchEvent로 길게 누르기·이동·스크롤 미차단·취소 처리 확인

아이폰/안드로이드 실물 기기에서의 터치 조작과 홈 화면 설치는 아직 검증하지 않았습니다. 드래그가 어려우면 선택 후 앞뒤 버튼으로 정렬할 수 있습니다.
